A command workspace for one person

One person may use several AI tools across software development, academic research, data analysis, writing, and project planning. High Command brings the project’s brief, imported conversation history, and manual work plan into one local workspace. I built it under my PhalAInx studio for people who need to keep that work organized across projects.

My role

I lead the product design, interface, desktop architecture, and implementation. I built the animated Home, resizable Command Deck, project and transcript organizers, manual tasks and milestones, Rust storage services, SQLite migrations, workspace backup controls, and Windows packaging. I also developed shared navigation, keyboard search, saved layouts, and configurable offline voice notifications.

What works in the Windows alpha

Projects retain their briefs, status, priority, and history. Imported conversations keep their original messages and order, with separate tags and links to one or several projects. Tasks and milestones add due dates, acceptance criteria, completion, and archive/restore controls. The Command Deck brings the linked records together, while search and Activity help the user find and resume work.

The Home screen is a functioning animated interface with interactive monitors. Four selectable local voice packs announce real workspace events, such as a saved project, an imported conversation, a backup operation, or a failure. Playback is queued, can be filtered or muted, and works without a speech-service connection.

Desktop architecture

LayerImplemented tools and purpose
InterfaceReact, TypeScript, and Vite build the shared interface, forms, navigation, and adjustable panels.
Windows hostTauri 2 runs the interface in WebView2, Microsoft’s embedded web renderer, and connects it to native commands and file dialogs.
Application servicesRust validates records and runs database operations separately from interface rendering.
Local storageSQLite stores projects, ordered messages, tags, links, tasks, milestones, settings, and migration receipts. The browser preview uses a separate IndexedDB workspace.

Protecting saved work

A stale editor cannot silently replace a newer save: each edit carries the revision it opened, and storage checks that revision before writing. Related records and links commit in one transaction, meaning the change succeeds as a whole or rolls back. Failed saves leave the form and draft available for retry. Imported message text stays separate from later organization edits.

Complete workspace backups include project records, conversations, tasks, relationships, archives, layouts, and preferences. Restore checks the file, identities, and relationships, then calculates a SHA-256 fingerprint from records read back from SQLite. This digital checksum must match one calculated from the backup before the transaction commits. A conflict or mismatch stops the import without keeping a partial addition. Schema upgrades are additive and tested to preserve earlier records.

Evidence behind the implementation

The release checks exercise the cases that can lose work: overlapping edits, failed reads and saves, rejected imports, database upgrades, backup round trips, and retry. The installed Windows host is checked separately from the shared browser interface, so a successful web preview is not used as proof of native startup.

Inspect the October 18 validation scope

The recorded baseline passed 89 JavaScript tests and 17 Rust tests using real SQLite, plus TypeScript, frontend-build, and Windows startup checks. The tests cover record validation, concurrent edits, rollback, schema upgrades, and verified workspace restore.

Browser checks exercised task and milestone creation, project links, completion/reopening, archive/restore, saved state after reload, failed-save recovery, stale editors, keyboard focus, and a narrow 390-pixel layout. An isolated installed-app check verified WebView2 startup and SQLite schema 2 with restored test records. Native file-dialog interaction, DPI, and full accessibility acceptance remain separate checks.

Current scope and next stage

High Command is in alpha testing. Its local project, transcript, and manual-work organization are implemented. Automatic conversation capture, live model connections, agent execution, and the execution controls behind Command Recall are later milestones. The gallery shows the working local interface, test records, and a recording of the native Windows Home screen.
