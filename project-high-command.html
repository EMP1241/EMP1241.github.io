High Command (HC)

v0.5.6 · Windows desktop alpha

I built High Command for one person juggling projects across AI tools. It keeps project briefs, saved conversations, tasks, and milestones together on the PC, with ways to resume interrupted imports and recover saved work. The Windows alpha is working; a separate Codex pilot can send prompts, show replies as they arrive, and ask the user to approve file changes.

Created by Brandon Santor under PhalAInx, my independent software studio.

Project at a glance ↓
Windows engineering

Close the app. Keep the work.

I separated the interface from the storage service so projects and conversations can survive closing or restarting the app. Tauri hosts the React interface; a supervised Rust service manages the local SQLite database and recovery.

Connected work

Briefs, conversations, and milestones stay together.

I built staged conversation imports that retain their progress across pause and recovery, then connect the saved history to projects and milestones. I also developed paged reading and checked full-message transfers so long histories can be inspected without opening every message at once.

Reliability

Recovery is part of the design.

I implemented operation records, revision checks, and coordinated closing to handle interrupted or competing saves. A result that cannot be confirmed stays visibly unresolved, and an older editor cannot silently overwrite a newer saved revision.

A command workspace for one person

One person may use several AI tools across software development, academic research, data analysis, writing, and project planning. High Command brings the project’s brief, imported conversation history, and manual work plan into one local workspace. I built it under my PhalAInx studio for people who need to keep that work organized across projects.

My role

I designed and built the application, from the animated Home and adjustable Command Deck to project organization, tasks, local storage, backups, and Windows packaging. Recent work focuses on keeping long imports resumable and making it clear what happened when a connection or command is interrupted.

What works in the Windows alpha

Projects retain their briefs, status, priority, and history. Imported conversations keep their original messages and order, with separate tags and links to one or several projects. Tasks and milestones add due dates, acceptance criteria, completion, and archive/restore controls. The Command Deck brings the linked records together, while search and Activity help the user find and resume work.

The Home screen is a functioning animated interface with interactive monitors. Four selectable local voice packs announce real workspace events, such as a saved project, an imported conversation, a backup operation, or a failure. Playback is queued, can be filtered or muted, and works without a speech-service connection.

Desktop architecture

LayerImplemented tools and purpose
InterfaceReact, TypeScript, and Vite build the shared interface, forms, navigation, and adjustable panels.
Windows hostTauri 2 runs the interface in WebView2, Microsoft’s embedded web renderer, and connects it to native commands and file dialogs.
Application servicesRust validates records and runs database operations separately from interface rendering.
Local storageSQLite stores projects, ordered messages, tags, links, tasks, milestones, settings, and migration receipts. The browser preview uses a separate IndexedDB workspace.

Read and import without loading the whole history

I built the reader and import pipeline to handle long histories in manageable pieces. The reader checks each continuation and keeps its source reference; full-message copy and export check the complete content outside the embedded browser. The import pipeline accepts supported text and JSON representations, saves progress, offers pause and resume, and makes imported records available only after verification.

The interface keeps record updates, import controls, and preference refresh separate so an unrelated slow read cannot stall recovery. Source changes and unsupported representations are reported explicitly. These improvements preserve the existing data limits; they do not establish unlimited conversation capacity.

Protecting saved work

I built revision checks into the save path so an editor opened before a newer change cannot silently replace it. Related records and links are saved together: the whole change succeeds or rolls back. I kept failed forms and drafts available for retry and separated imported message text from later tags and project links. Those decisions protect both the original history and the user’s organization work.

I implemented complete SQLite workspace snapshots and restore checks for their content and relationships. I retained a legacy JSON compatibility route, with explicit refusal when it cannot represent the requested data. I exercised interrupted imports, lost replies, recovery, and snapshot/restore in packaged checks using an isolated workspace.

Evidence behind the implementation

The latest recorded delivery checks exercise the cases that can lose work: interrupted imports, duplicate retries, lost replies, conflicting edits, service loss, close/reconnect, schema upgrades, and snapshot/restore. The portable and isolated installed applications were checked separately from the browser fixtures.

Inspect the October 22 delivery and validation scope

The October 22 recovery-and-authorship delivery records 167 JavaScript tests, 185 native tests, 137 rendered-interface checks, and eight pipe-codec checks. These cover different layers rather than one combined test count. Packaged and isolated installed applications also passed the recorded cross-format import, interruption, and reader scenarios.

Browser fixtures use synthetic records and native mocks; packaged checks exercise the actual Windows storage process, private pipes, SQLite, imports, and restore. Native file-picker interaction, actual clipboard publication, clean-machine qualification, and full accessibility acceptance remain separate. The source and package retain the existing capacity limits.

A tested session, including the interruption

I built the pilot to keep a prompt and its response tied to the same project and session. In a live interruption test, HC retained the text already captured and the original session, send, and turn identities without automatically sending the prompt again. When the final response could not be recovered, the interface kept that outcome visibly unknown instead of presenting partial text as a completed answer.

Inspect the October 23 pilot checks and remaining scope

The live record covers five test turns in one HC-owned session: an exact response with Unicode preserved, a confirmed stop, an approved file addition, a denied addition that remained absent, and interrupted-stream recovery. Authenticated restart reconnected to the same session.

Supporting checks covered fifteen process scenarios, nine interface checks, and twelve packaged import/close/resume scenarios. These test recovery, approval handling, and the local storage path; they do not establish compatibility with every command, account plan, or client version. Existing capacity limits remain unchanged.

Stop a command and see what happened

I extended the pilot with a staged command-recovery workflow that records the command, user approval, captured output, and outcome. It checks whether its command has ended after Stop or a disconnection, and reconnecting does not automatically send the request again. An outcome that cannot be confirmed stays marked unknown. This work remains in the separate staged build described below.

Inspect the staged command-recovery checks and delivery limit

The October 23 record covers actual PowerShell completion, Stop, disconnect, and restored command records in an isolated test build. Stop cleanup took 206 milliseconds and disconnect cleanup took 18 milliseconds in those tests. Supporting suites recorded 193 SQLite tests, 176 JavaScript tests, 31 connection checks, and 12 packaged scenarios.

The test build allowed three processes. The delivered configuration still allows two, already occupied by its existing services, so those PowerShell tests do not establish command execution under the shipped limit. The staged build has not been promoted to the regular or opt-in launcher. Broader command compatibility and qualification remain open.

Current scope and next stage

The normal launcher opens the delivered project-organizing alpha. The opt-in launcher adds one tested Codex session. The newer command-recovery build remains separate while its delivery limits are resolved. Connections to other providers, including Gemini and Claude, and coordination between multiple models remain planned work rather than current capabilities.

High Command and Research Architect

High Command serves one person managing work across AI tools. Research Architect gives each member of a human team a configured AI assistant and connects their work through shared methods, context, review, and handoffs. They are separate products from PhalAInx.
