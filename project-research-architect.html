Research Architect

Research Architect is my framework for building AI-assisted research systems for human teams. It converts a reviewed project design into an individual assistant kit for each participant. Every kit identifies its human operator, assigned workstream, methods, dependencies, and first action; the team then works through a shared system with review and handoffs.

The Hub coordinates shared work and reviewed releases; Spokes are the individual assistants configured for assigned research; the Ingestor organizes incoming evidence and runs file checks. My Python generator builds these role kits and their working folders. A small HTML interface lets people inspect incoming files, revisions, receipts, and review history.

Research behind the architecture

A technical white paper and comparative literature review document the design. I reviewed thousands of research and technical sources and turned them into workflow instructions for citing evidence, comparing methods, surfacing conflicting findings, preserving uncertainty, and keeping a human reviewer responsible for decisions. This shaped the research process; it did not retrain the underlying AI models. The public literature review lists 25 cited entries; the broader source review informed the framework’s instructions and methods.

Part of that foundation comes from FAIR data principles (making data findable, accessible, interoperable, and reusable), W3C PROV (a standard model for documenting where data came from and how it changed), digital-repository guidance, and AI risk-management work. The scientific library contains 16 practical method guides. My technical white paper documents the architecture and its use in the New World Screwworm project, including receipts, recovery checks, and Research Architect 2.1 release verification.

From an assignment to a verified handoff

Each contributor package includes a file list and SHA-256 fingerprints, which help detect missing or changed files. Version checks stop work from starting from an outdated checkpoint. The system writes partial work separately, then checks the published copy before it can replace the current version. Separate review, delivery, and acknowledgement records show what was approved, sent, and received.

I used Research Architect to generate the New World Screwworm coordination system, configured its deployment, and supported onboarding eight people. The independent Spatial Evidence Workbench is a separate application; the RA white paper assesses the framework and generated Hub workflow.

Research that survives a new session

When a project starts, the system locates its designated current checkpoint. New snapshots preserve earlier states, and a routed index points researchers back to source files and prior decisions. For long histories that exceed one response, context-restoration steps carry the material forward in parts while preserving the original text and operating rules.

Backup tools compare copied files with their originals and support restoration in an isolated test. An October 16, 2026 inventory recorded 262 package transfers in the deployed Hub: 98 incoming and 164 outgoing. These are handoff records, not counts of people or AI tasks; dispatch receipts separately show which deliveries were completed.

171 automated tests

RA 2.1 distribution revision 2 passed 171 repeatable software checks, organized into 11 groups, on Windows with Python 3.12.10. There were no failures, errors, or skipped checks. The tests check software behavior; they do not evaluate research conclusions.

701 exchange files

During the October 13, 2026 Hub runtime upgrade, SHA-256 fingerprints for 701 checked exchange files matched before and after the change. That confirms the files were preserved through the software upgrade.

123,098 recovered files

A separate October 11, 2026 recovery exercise restored and hash-checked 123,098 saved files in an isolated environment, without accessing live project sources. This checks whether the backup could be recovered; it is not a research-data sample size.

My October 16, 2026 technical white paper and retained test records document these checks. Release tests check kit generation, saved project state, package exchange, handoff rebuilding, and recovery.
