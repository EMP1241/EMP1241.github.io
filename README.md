# Brandon Santor · Geospatial Research & Software

Static personal portfolio with nine case studies: New World Screwworm research, the independent Spatial Evidence Workbench, Mars Explorer, COLE, Tree-Ring Atlas Explorer, Thermal Vent Atlas Explorer, Research Architect, smartphone GNSS research, and High Command. An unlisted PhalAInx studio page is linked from Research Architect and High Command. PhalAInx is Brandon's independent software studio. Research Architect is a human-team research framework; High Command is a personal multi-model application in alpha testing.

Open `index.html` in a modern browser or serve the repository root with a static HTTP server. No build or package installation is required.

- `index.html` features the New World Screwworm project and its broader research, GIS, and evidence-integration work.
- `about.html`, `projects.html`, and `resume.html` provide the main sections.
- Nine listed case studies and the unlisted studio page each have a three-item gallery. High Command has two screenshots and a five-second Home-screen recording. The NWSW and Research Architect pages use architecture diagrams; the PhalAInx studio page shows genuine packaged-prototype captures. The workbench page shows real QA application captures. `project-phalainx.html` presents the studio; `project-research-architect.html` presents its research framework.
- `resume.pdf` is a sanitized public résumé generated from `resume.html` by `tools/build_resume.py`, keeping the page and download on the same source of facts.
- `assets/documents/research-architect-white-paper.pdf` is the author-provided revised white paper; explicit links open it in a separate browser tab without an embedded PDF viewer.
- `site.js` provides the saved theme preference, legacy fragment redirects, and résumé print control.
- `gallery.js` provides manual carousels and a keyboard-accessible native-dialog image/video viewer with image fit/full-resolution controls, native video controls, loading/error feedback, and focus restoration. Gallery clips pause when hidden, off-screen, or effects are paused; reduced-motion users retain manual playback.
- `project-intro.js` starts the PhalAInx introduction when a visitor uses a legacy studio link with `?intro=1` or chooses replay, with Skip, native playback controls, replay, reduced-motion handling, and failed-playback recovery.
- `style.css` contains responsive layouts, dark/light themes, reduced-motion support, and print styles.
- `research.css` adds project-specific decorative motifs, workflow diagrams, studio branding, and the expanded résumé layout. Each project header has a labeled tools-and-methods tag list; Research Architect and High Command have separate project entries and credit PhalAInx as the independent studio. The studio page retains its old URL but has no directory card or project rank; `noindex, follow` requests search exclusion without providing access restrictions.
- `workflow.js` changes the headline and input/process/output diagram for each 01–04 stage, with keyboard navigation. All stages remain readable without JavaScript.
- `motion.js` provides bounded parallax, rotating hero highlights, one-time scroll reveals, and the persistent pause control. The CSS adds slow ambient motion to every hero banner. Effects respect reduced-motion preferences, pause while the page is hidden, and pause on request.
- `assets/icons/` contains original TRAE, TVAE, PhalAInx, and author-supplied Research Architect artwork. Mars and COLE use interface-derived marks.
- `assets/screenshots/` contains reviewed application captures and author-supplied research figures. Its README records provenance and limitations.
- `assets/video/` contains the original PhalAInx branded introduction and a five-second native Windows HC Home recording, with their provenance.
- `assets/tamu-white.svg` is the official white university mark used in the header.

Dark mode is the default. Theme and optional effects preferences are saved locally in the visitor’s browser. Core navigation, case-study content, image links, and native video playback work without JavaScript. Image galleries do not advance automatically. Current product-page studio links open the studio directly, with manual introduction replay. Legacy studio links containing `?intro=1` still start its 10-second clip muted in a native dialog and reveal the studio when it ends or is skipped. The query is consumed so a refresh does not repeat it. Direct visits retain manual playback and replay. Reduced-motion visitors get manual Play; failed autoplay keeps controls and Skip available. Playback pauses when the page becomes hidden. Old home-page fragments redirect to corresponding pages.

The public pages and résumé include only the approved TAMU email address, brandon.santor@tamu.edu, with a mailto link. Personal email addresses, phone numbers, and postal addresses remain excluded. Private CV/résumé originals, raw research packages, private evidence records, and imported user datasets are excluded. Both QR codes in the author-selected GNSS figures are preserved: they link to the author's existing public research PDFs, whose original contents are outside this repository. Screenshot controls are static illustrations, not embedded running applications.

GNSS figures distinguish the measured campus study from an illustrative present-day New Orleans scenario. The companion layout shows how overlapping modeled buffers form an approximately 50-acre footprint; it is not a reconstruction of historical Katrina calls.

Before publishing, run `python tools/check_site.py`, `node --check site.js`, `node --check gallery.js`, `node --check project-intro.js`, `node --check workflow.js`, `node --check motion.js`, and `git diff --check`. The validator checks the exact gallery count and thumbnail indices. Browser checks should cover desktop/mobile layout, gallery wrapping and thumbnails, repeated lightbox open/close, keyboard/focus behavior, zoom, failed-image recovery, theme persistence, project-entry video, skip/replay/end cleanup, and navigation.

GitHub Pages serves the repository root from `main`. Push using an account with write access.

For resume edits, run `python tools/build_resume.py` with ReportLab and pypdf available, render the resulting PDF, and inspect both pages before publishing. `python tools/build_resume.py --check` verifies that the download's embedded source fingerprint matches the current `resume.html`.
